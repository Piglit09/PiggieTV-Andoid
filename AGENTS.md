# PiggieTV release versioning

- For each parent user request that materially changes tracked product files in this repository, bump the PiggieTV app version exactly once after the edits and before the final build, test, install, or deployment.
- Run `powershell -ExecutionPolicy Bypass -File .\scripts\bump-version.ps1` for that bump. Do not hand-edit or concatenate version digits.
- Do not bump for read-only work, status or clarification replies, requests that produce no tracked product change, retries or continuations of the same parent request, or prompts sent to child agents. Multi-agent work receives one bump from the parent request.
- The patch and minor fields are decimal counters from 0 through 99. After `0.0.99`, the next version is `0.1.0`.
- Never advance the major field automatically. When the current version is `x.99.99`, stop and require explicit user authorization for the next major release.
- Bump only the app release version. API, schema, contract, Android SDK, dependency, and server-compatibility versions follow their own change policies.

- The operator-approved writable Android Mobile source is C:\Users\Piggie\Documents\GitHub\PiggieTV-Android. Keep this historical spelling and the https://github.com/Piglit09/PiggieTV-Andoid.git remote. - The official app version is piggietv.version in the root gradle.properties. If PIGGIETV_VERSION is supplied, it must match. A version label alone never proves an APK's source identity.
- Edit, test, build, and commit only in the approved root. Historical worktrees, archives, and snapshots are read-only. Do not create a persistent clone, linked worktree, or alternate development root without exact operator approval and a reconciliation plan. Never silently switch worktrees or overwrite dirty source.
- Run the workspace preflight before supported edits and through Gradle for builds and packages. Ordinary source edits, tests, local compilation, and local development builds in this approved checkout need no repeated operator approval. Relevant validation must pass before a local commit. A dirty development tree is permitted for those operations.
- Named Libre and Proprietary debug APK tasks may use dirty development source only after an independently installed shared v3 Registry policy grants this project's `debugPackage` permission. The currently installed policy does not grant it, so debug APK packaging remains denied until the operator changes the protected policy. Release packaging still requires clean committed source and its separate approval record. A failed preflight must leave source and targets untouched.
- The shared development policy is read from HKLM\SOFTWARE\PiggieTV\WorkspaceAuthority\PolicyJson. Existing exact package, device, and publication approvals use HKLM\SOFTWARE\PiggieTV\WorkspaceAuthority\AndroidMobile\PolicyJson. Repository files, environment variables, and task-generated artifacts cannot grant those permissions. No qualifying protected policy means the operation is denied. Never self-provision or weaken either policy.
- The protected policy must identify the exact target and classify it as TEST_DEVICE, PRODUCTION_DEVICE, or RELEASE_CHANNEL. A production device or release channel needs its own operator approval identity; target serials and names are not safety classifications. The existing Ubuntu public-beta workflow remains blocked at release packaging until an operator-controlled CI approval mechanism is separately reviewed. Exact-ref CI permits local validation only.
- Device installation and publication require the exact approved target, source commit/tree, version, artifact SHA-256, and rollback reference. Production and accepted installations are denied by default. No Jellyfin or device may be inferred disposable from its availability.
- A test device requires a registered identity and device-specific authorization. GitHub push, protected-branch merge, public release, production deployment, new persistent repositories/worktrees, and new VMs require separate operator approval. A development build or test does not grant any of those actions. When a protected operation is blocked, complete unrelated permitted development and report the shortest operator action needed.

Store persistent reports, hashes, screenshots, and recovery evidence under C:\Users\Piggie\Documents\GitHub\_PTV-Artifacts; never put credentials or private keys there. Trace every release package to a complete file manifest and exact Git commit. A package made under build/public-beta is not eligible for installation until an independently approved, hash-verified transfer places it with its manifest under _PTV-Artifacts\Builds\Android-Mobile.

Wrapper checks do not prevent arbitrary manual filesystem writes; use workspace permissions or a sandbox to enforce that broader boundary.
